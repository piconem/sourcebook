# Sourcebook 0.2.0

*2026-11-05 · from a single-user notebook to a self-hosted application for teams of people and AI agents — with
the user always in control.*

## Highlights
- **People**: sign-in, an owner account, users with **read** or **write** access per project.
- **Agents**: one personal access token per person, any number of named agent identities (a writer, a reviewer…),
  every contribution signed *"Reviewer · for Alex Morgan"*.
- **Locks**: take a block while you (or an agent) work on it.
- **CSV data** blocks: reference data sets to reason about, with table, column summary and comments on rows.
- **Docker**: a versioned image, docker compose, configurable workspace, port and base path.
- **Five templates in every installation**, including the new *Sourcebook Demo* tour.
- **Reading comfort**: zoom of the document, a hideable sidebar, light text blocks in dark themes.
- Works with **Claude Code, Gemini CLI, OpenAI Codex** and any MCP client.
- New logo, a new README and documentation split into guides, **MIT license**.

## People, access and accounts
- Sign-in with username and password; web sessions in secure cookies; repeated wrong passwords are throttled.
- The **owner** account is created at the first start (password from `SOURCEBOOK_ADMIN_PASSWORD` or printed once in
  the log) and must be changed at the first sign-in; `reset-owner-password` prints a new temporary one.
- The owner adds users (temporary password changed at the first sign-in), disables, resets or deletes them, makes
  them owners, and decides who may create projects.
- **Access per project and template**: read (read and comment) or write; projects without access are invisible.
- Profile pictures for people and agents, cropped square in the browser and shown in circles everywhere.
- Accounts stored in the workspace, in `.sourcebook/`: scrypt password hashes, SHA-256 hashes of tokens and sessions —
  never the passwords or tokens themselves. Back up the workspace and everything comes along.

## Agents
- **One MCP configuration per person**: a personal access token (shown once); every agent of that person shares it
  and names itself in each call (`agent: "reviewer"`), or the person's default agent acts.
- Agents are registered by their person (Settings → My agents) or by the assistant itself (`register_agent`); ids
  are unique across the installation.
- An agent never has more rights than its person. **Revoke** stops it and keeps its history; **Delete** removes it
  for good with everything it wrote — threads, replies, resolutions, notifications, locks — after showing what will
  go, and frees its id.
- `whoami` and `list_participants` tell an agent who it is, whom it works for and who else is in the project.

## Locks
- Take a sub-block (🔒 in its header, or `lock_subblock` for agents): until it is released nobody else can change or
  delete it, nor delete its section; comments stay open.
- The holder releases it; a person may release their agents' locks; the owner can release any (in the editor or in
  Settings → Locks).

## Notifications
- Unread notifications are marked where they apply: a badge on the section in the outline and a bell on each changed
  block. Clicking the badge goes to the change; a notification is marked read only from the block's bell or the
  top-bar menu.
- Notifications are read per person.

## Editor
- **CSV data** sub-block: data stored in the project (`.csv`); table with sorting, filtering, pagination and editing
  of cells and column names; rows and columns added and removed; **summary per column** (type, empty cells, distinct
  values, min / max / mean, most frequent values); raw CSV; import from a file or from References (delimiter
  detected) and download. Comments attach to rows; agents address rows as lines.
- Collapsible outline (per section, or expand / collapse all; remembered per browser and project).
- References: move files and folders by dragging them onto a folder or with "Move to…" — links and attachments follow.
- Read-only view for people with read access (comments stay available).
- About dialog with version and release date; license and third-party licenses.

## Reading and layout
- **Zoom** of the document area only, as in a word processor: − / + in the top bar, a click on the percentage resets
  it to 100%, Ctrl + mouse wheel over the document (50%–200%, remembered per browser). The top bar and the outline
  keep their size; drawings and code stay sharp and clickable at every level.
- **Hide the sidebar** (button left of the logo, or Ctrl+\\) to give the document the whole width; remembered per
  browser.
- Appearance → **Blocks in dark themes**: dark like the theme, **light text** (Markdown blocks light for reading;
  code, data and diagrams stay dark) or light blocks.
- Section and sub-block headers wrap instead of overflowing at large zoom levels or in narrow windows.
- Fixed: a drawing appearing on screen made the whole page blink for a moment (Excalidraw's loading screen covered it).

## Comments
- A clearly visible delete button on each thread, comment and reply, with an inline confirmation.
- Resolved threads can be deleted one by one or all at once (in a block's comments panel and in All comments with
  the *Resolved* filter). People with read access delete only what they wrote.

## AI assistant (MCP)
- Connection commands for **Claude Code, Gemini CLI and OpenAI Codex** (command and `config.toml`), plus JSON for other
  clients, in Settings → AI assistant and, with the token filled in, in Settings → My agents.
- New tools: `whoami`, `register_agent`, `list_participants`, `lock_subblock`, `unlock_subblock`, `list_locks`,
  `move_references`.
- CSV sub-blocks read and edited like any text; comments on rows.
- stdio is unavailable when Sourcebook runs in a container (it would need a process on the client's machine); HTTP
  works everywhere. `SOURCEBOOK_MCP_STDIO` overrides the default.

## Installation and deployment
- Startup configuration by options or environment variables: workspace folder, host, port, **base path** (e.g.
  `https://mydomain.it/marco/sourcebook/`), public URL, initial owner password, reverse proxy.
- One build of the web client works under any base path; several instances can share a domain.
- **Docker**: multi-stage image (`docker/Dockerfile`), `build.sh`, `docker-compose.yml` with `.env` settings,
  `push.sh` to publish on GitHub Container Registry for amd64 and arm64; unprivileged user, one `/data` volume,
  health check, clean shutdown. Guides for reverse proxies (Caddy, nginx) and Windows.
- `pnpm start` builds the client and serves everything from the server.

## Security
- Uploaded and reference files (SVG, HTML…) opened directly in the browser run in a sandbox, so a file cannot act with
  the rights of whoever opens it.
- Every response carries `X-Content-Type-Options: nosniff`, same-origin framing only and `Referrer-Policy:
  same-origin`.
- Dependencies updated (MCP SDK, zod, fastify and others) to fix known vulnerabilities; fixed versions forced for
  libraries bundled by Excalidraw, mermaid and remark (`overrides` in `pnpm-workspace.yaml`).
- Security section in the [Docker guide](../../docker/README.md#security): what the image does and what is up to you
  (HTTPS through a reverse proxy, first password, backups).

## Templates
- Every new installation gets five templates, each added once (a template the owner deletes does not come back):
  **Sourcebook Demo** (a tour with a block of every type, references, bibliography and pages on collaboration and
  agents), **Software Project**, **Scientific Paper**, **Research Project Proposal**, **Thesis**.
- The example templates are defined as JSON in the server; `scripts/create-example-templates.py` reads the same files
  and now authenticates with an access token.

## Documentation and project
- New logo (application, favicon, README).
- README rewritten: what Sourcebook is, the user in control, ways of working, projects, templates, screenshots,
  getting started with Node or Docker.
- Documentation in `docs/`: installation, user guide, collaboration, AI assistant, REST API, file format, development,
  libraries and licenses, screenshots, design decisions.
- **MIT license**; `THIRD_PARTY_LICENSES.txt` generated at build time and included in the application and the image.
- `scripts/release.sh`: `prepare` sets the version everywhere and drafts the notes, `publish` checks, tags, pushes and
  creates the GitHub release (see [Releasing](../development.md#releasing)).

## Upgrading from 0.1.0
- At the first start the profile of the single-user version becomes the **owner** account, so existing comments stay
  signed by it; a password is generated and printed in the log, to be changed at the first sign-in.
- MCP clients must be configured again with an access token (Settings → My agents).
- The MCP settings move from `~/.config/sourcebook/` into the workspace (`.sourcebook/settings.json`).
- The four example templates already in the workspace are left as they are; Sourcebook Demo is added.
